## 描述

DeepSeek Harness Git 插件 —— 在会话视图里提供 Git 页，用于查看 diff 与执行 Git 操作。

## 功能介绍

- **会话 Tab 栏新增 Git 页** —— 在 对话 / 轨迹 / 终端 之后多一页，切换方式完全一致。
- **一条工具栏，按使用顺序排列** —— 左栏首行依次是工作区名称、当前分支和刷新按钮，两者的名字都只出现在悬停提示里，分支的提示内容就是完整分支名；宽度不足时，这一行最先让位的也是分支名——先缩成省略号，最后只剩分支图标，工作区名称要等分支只剩图标之后才开始收缩。下面是 变更文件区、提交历史，右侧 Diff 查看区占满其余会话区域。远程操作按钮不在首行，而在 提交历史 标题行的右端，正对着面板自己的名称与条数、紧挨着它要移动的那些提交。
- **切换分支** —— 点击首行的分支名打开切换分支对话框：列表按「当前分支、本地分支、远程分支」三段排列并各带标题，段内仍按提交时间倒序，顶部搜索框同时过滤这三段；当前所在分支就是首段里的那一行，并在对话框打开时即为选中项——单击可改变选中项，选中行与鼠标悬停用同一种背景色，所以指针移到页脚按钮上时依然看得出选中的是哪一行；输入即时过滤三段列表，Esc 关闭，真正切换只由页脚的按钮完成，单击任何一行都不会切换。选中远程分支时会切换到跟踪它的本地分支，该本地分支不存在则新建。对话框只负责发起切换，判定交给 Git：被拒绝时（例如有未提交的改动挡路）和页面其它失败一样走同一个错误对话框，并带上 Git 指出的文件。切换会改动工作区，因此页面会重新读取仓库，并放弃原来显示的 Diff。
- **两条分隔线都能拖动，尺寸也会被记住** —— 左栏右边缘调整宽度，变更文件区与提交历史之间的分隔线调整上下比例；指针移上去时对应的一条线会变亮，拖动期间整页光标都跟着变成该方向。侧栏最小 260px（再窄自己的工具栏就放不下），Diff 查看区至少保留 320px，两个面板各自不低于 96px（一个标题加两行），窗口再矮也如此。宽度按像素、上下比例按占整列的比例，都记在本插件自己的 `localStorage` 键下，所以下次打开还是上次的样子；宽窗口里存的宽度到了窄窗口会被收窄而不是把 Diff 查看区挤没，高窗口里存的比例也会按当前高度重新分摊。
- **同步变更** —— 分支有上游时出现在 提交历史 标题行的右端，按钮内部是上下两个箭头和各自的提交数（`↓` 落后、`↑` 领先，始终显示、为 0 也是数字），悬停提示把这两个数写全：`同步变更 · 待拉取 N · 待推送 M`。一个按钮完成整轮同步：先把当前分支从上游快进，再推送剩下的提交。先拉取是推送不会因为落后而被拒绝的原因；历史已经分叉时直接拒绝而不是合并，所以这个按钮不会凭空造出合并提交，也不会把工作区留在冲突状态，拉取被拒时整轮同步就此停止。
- **发布分支** —— 分支还没有上游时以单个图标取代「同步变更」出现在同一位置：这种分支没有分叉可报、也没有可拉取的对象，需要的是一次推送——把它推到唯一的远程仓库，并由这次推送把该远程记为它的上游。没有远程或存在多个远程时会说明情况，而不是猜一个。
- **错误统一用对话框** —— 所有失败都弹同一个对话框：切换分支被拒、提交被 Git 拒绝、拉取或推送被远程拒绝、Host 无法回答的读取。目录不是 Git 仓库不算失败，这种情况仍由面板就地说明。操作成功不弹提示，重新读取后的页面本身就是结果。
- **变更文件** —— 列出 `git status` 报告的全部路径（已暂存、未暂存、未跟踪、重命名、删除、冲突），并保留每一行在索引与工作区的状态：每行依次是状态字母、文件名、以及 `·` 之后的父目录相对路径——父目录比它前面的文件名更淡，位于仓库根目录的文件没有这一段。工作区干净时列表里什么都不画，因为标题行的 `文件变更 · 0` 已经把话说完了；计数为 0 时标题照样写出数字，提交历史 的标题也一样。悬停的行与选中的行共用同一种背景色——与切换分支对话框遵循的是同一条规则——所以指针移开之后，页面停在哪一行依然看得出来。悬停时列表行旁边还会把这一行写全，读作 `路径 · 状态`：先是完整的仓库相对路径（重命名时旧路径跟在后面），再用标题行同款的 `· ` 接上文字写出的状态——行内本身只放得下一个字母和一段被省略号截断的尾巴。气泡最宽 500px——这是本插件画出的每一个气泡统一的上限，取代原语按视口一半计算的上限，所以气泡的形状不再随窗口变化——很长的路径会在气泡内换行，而不会横着撑满旁边的面板。
- **提交** —— 侧栏自己的一行，在工具栏下方、变更文件区上方：一个全宽的 `Commit Message` 输入框，下面一行是全宽的 `Commit` 按钮。输入框是本插件自己实现的多行输入框——回车即换行，高度随内容增长、最多长到 4 行，再多就改为滚动，所以标题和正文都写得下，也不会把 变更文件区 往下挤——圆角与按钮保持一致，因为这两行是一个表单。输入框里按 ⌘/Ctrl+Enter 可直接提交，按钮则是常规路径。工具栏与输入框之间不画任何线，所以这两行与工具栏读作一整块，整块由表单底部的一条分隔线与 变更文件区 分开。点一下就会把 变更文件区 列表里的改动全部暂存——已跟踪的修改、删除、以及未跟踪的新文件都算在内——再用这条信息把它们记成一次提交；整个过程是一次请求，所以页面不会留下一个半暂存的索引。没有填写信息、没有可提交的改动、或已有其它操作正在进行时按钮不可点。提交成功后清空输入框、放弃刚被提交掉的 Diff 并重新读取页面；存在未解决的冲突时会拒绝而不是暂存，提交被拒时输入框内容原样保留。
- **Diff 查看** —— 点击文件查看它相对 `HEAD` 的改动（未跟踪文件与 `/dev/null` 比较）；点击提交查看整次提交的完整补丁，按文件分区，带双侧行号与每文件 `+N −M` 统计。
- **提交历史** —— 最近提交及其作者、时间、分支/标签装饰；合并提交与第一个父提交比较。
- **复制** —— Diff 头部的按钮复制的就是屏幕上这段补丁。
- **主题自动适配** —— 基于 DSH 主题变量渲染，兼容大多数主题插件，明暗两种外观都正常。

## 安装教程

使用 DSH 的新增插件功能，输入包名：dsh-cool-git 即可。

安装或更新后请重载 / 重启 DSH：浏览器端刷新页面即可生效，但 Host 端的路由是在插件挂载时注册的。

## 目前存在的几个限制

- 不做逐文件暂存，也没有新建与删除分支：提交时提交的是列表里的全部改动，否则不提交。页面能改动的有四件事：切换分支、同步变更（先快进式拉取，再推送）、发布还没有上游的分支，以及侧栏提交表单发起的那一次提交。仓库自己的钩子照常执行——`git commit` 没有加 `--no-verify`——钩子拒绝时按它给出的原因如实报出。
- 同步里的拉取只做快进：两边已经分叉时页面会说明原因并停止，不会继续推送；合并或变基请自行处理。
- 页面不会弹出凭据输入（`GIT_TERMINAL_PROMPT=0`），所以本机没有现成凭据的远程会直接报认证失败。
- 领先/落后计数来自 `git status`，其新鲜度取决于上一次 fetch：别的机器推上来的提交，在下一次同步之前是看不见的。
- 所有写操作都需要会话自身的写权限：在只读模式下分支不会变，页面会说明原因。
- 提交历史最多 60 条，超过 4 MiB 的补丁会被标记为已截断。

## 参与贡献

欢迎提交 Issue 和 PR。

客户端图标放在 `src/client/assets/*.svg`（24 网格的 Tabler 图稿）。浏览器端是以单个 JS 文件加载的，所以这些 SVG 不会在运行时被请求：`tsdown.config.ts` 在构建时把它们内联成按文件名索引的表，`src/client/icons.tsx` 再把它变成组件。新增一个图标只要放进文件并导出对应组件，不需要改配置。

```
// 克隆项目
git clone https://github.com/CoolTea001/dsh-cool-git.git

// 安装依赖
cd dsh-cool-git
pnpm install

// 启动本地开发
pnpm run dev

// 本地安装：使用 DSH 的新增插件功能，输入本地项目路径即可

// 重启 DSH 服务
dsh web
```
